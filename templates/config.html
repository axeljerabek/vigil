Cameras

Add, edit, or remove cameras here — no need to touch config.py anymore. Saving restarts the recording pipeline automatically so new cameras start being watched right away. The live preview for a brand-new camera specifically needs the dashboard itself (web_ui.py) restarted too — everything else (recording, detection) works immediately. Each camera has two independent toggles: Video (object detection + recording) and (this camera's microphone feeds the audio trigger, if enabled globally in Settings above — turning it off here only affects this one camera).

AI Video Analysis (Ollama)

Optional: after each recording, sends the large filmstrip frames (see above, must be > 0) to a self-hosted Ollama instance with a vision model and has it describe what happened in the video. Off by default — needs a running Ollama instance with a suitable model, e.g.: docker exec -it ollama ollama pull llava:latest (~5-8 GB VRAM in addition to the pipeline). Just leave it off if you don't run Ollama. Important: Ollama has no native video support — every model always receives an image sequence (the filmstrip frames), never the video file itself. For unfamiliar/untested models, check first whether they actually process images at all (some "uncensored" finetunes are text-only models with no vision support).

Each analyzed frame costs roughly 1000-1100 tokens (varies by model/resolution) — so at "Max. frames per analysis" = 64, a full batch needs around 65,000-70,000 tokens total. Audio Trigger (CLAP, optional)

In addition to image detection: also triggers a recording when a configured sound is detected — regardless of whether anything is visible in the frame. Uses CLAP, a model that compares audio directly with freely entered text — no fixed category list like classic sound classifiers. One category per line, any number active at once, e.g.: whispering, glass breaking, dog barking, screaming. Runs in its own background thread — never blocks recording, even with a slow or missing GPU. Requires pip install transformers in the venv; without it, the feature simply stays inactive (no error).

Topic Classification (via Vision Model, optional)

Adds a second question to each AI analysis: how well does the scene match one of your own categories, e.g. break-in, accident, mail carrier? One per line, any number. The best-matching category (if above the threshold) is shown next to the description, saved to the sidecar metadata, and searchable. Honest caveat: this is the vision model's own self-reported guess via a prompt — not a calibrated probability like the detection confidence above. Treat it as a useful sorting signal, not a certainty. Requires AI Video Analysis (above) to be enabled.

Speech Transcription (Whisper, optional)

Transcribes spoken audio from each recording using a locally-run Whisper model — separate from the audio trigger above (CLAP only recognizes sound categories, not actual words). The result is saved to the sidecar metadata and is semantically searchable, just like the AI description.

Face Recognition (optional)

Detects faces in each recording, groups similar ones together, and lets you name the groups in the People section below. New faces are checked against already-named people automatically; anything unmatched needs a "Re-cluster" run (People section) before it can be named. Runs entirely locally via InsightFace.

Storage

Where recordings actually live. By default, everything is stored inside the project folder itself — on the same drive as the system, if that's where vigil is installed. Point this at a separate, larger drive if you expect to record a lot. Changing this does not move existing recordings — only new ones, from the next pipeline restart onward, go to the new location. See the Storage Status card below for live disk space per configured folder.

Export

Copies the video, thumbnail, and all sidecar metadata for an event into its own folder, named e.g. Event_Garden_20260830_081734 Topic_Accident. Leave empty to hide the Export button. Two destination types: local path (e.g. /mnt/backup/vigil-exports) copies directly; remote path (e.g. user@host:/path) uses rsync — this requires passwordless SSH key access to already be set up between this machine and the remote one; nothing here can configure that for you.

Applies to every future export (single or bulk) until changed here again.

Only deletes once the export is confirmed successful — never if the export fails partway through. Off by default; this is permanent, there's no undo.

Watchfolder Import (optional)

Watches a folder for video files dropped in from elsewhere (e.g. a phone backup, an old NVR export, a network share) and imports them automatically once a file has stopped growing — treats each as a finished recording: renamed, filmstrip generated, and run through the same AI post-processing as a live camera event. Runs as its own background process; enabling/disabling requires a pipeline restart (automatic if the pipeline is already running).

How long a file's size must stay unchanged before it's considered fully written and safe to import — Linux has no reliable "file is done" signal, so this is a practical stand-in. Raise it if you're importing over a slow network share.

Only works for streamable sources (MPEG-TS, or "fast-start" MP4 with the index written first) — checked automatically per file. A classic MP4 that only becomes readable once finished falls back to waiting, same as with this off. Runs the file through the same detection/recording pipeline as a real camera instead of a blind import at the end.

Home Assistant / MQTT (optional)

Publishes camera events to an MQTT broker — a "Recording" motion-style sensor per camera (on while a recording is in progress) and a "Last Event" sensor with the AI description, once analysis finishes. With Home Assistant Discovery enabled (default), these appear automatically under Settings → Devices & Services → MQTT in Home Assistant, no YAML needed. Requires pip install paho-mqtt in the pipeline's virtual environment. Off by default; never blocks or slows down recording even if the broker is unreachable.

Events publish under <prefix>/<camera>/recording and <prefix>/<camera>/last_event_summary — useful for your own automations even without Home Assistant.

Agent Webhook (optional)

Proactively notifies an agent (Hermes, or your own script) after each analyzed recording, instead of it having to poll for changes. Fire-and-forget, same as MQTT — an unreachable agent never delays or affects the pipeline.

Leave off to get every analyzed event; turn on if you only want the agent to hear about the unusual ones (needs Anomaly Detection enabled above to have any anomalies to report).

Pose Estimation / Fall Detection (optional)

A separate, small pose model runs only on frames where a person was already detected — no extra GPU cost on empty scenes. Flags a likely fall based on torso angle (near-horizontal instead of upright) sustained over several consecutive frames, not a single frame, so a brief bend (tying shoes, picking something up) doesn't trigger a false alarm. This is a heuristic, not a calibrated medical tool — the angle threshold is adjustable if it's too sensitive or not sensitive enough for your cameras. Requires a pipeline restart to take effect. Off by default.

Lower = more sensitive (flags more postures as falls, more false positives from bending). Higher = only near-fully-horizontal counts.

Anomaly Detection (optional)

Flags recordings whose AI description is a statistical outlier compared to that camera's recent history — reuses the same semantic-search embedding that's already computed for every event, no new model or GPU cost. Needs a per-camera baseline (train from the Summaries card, or via cron) before it can flag anything; a camera needs at least 15 analyzed recordings in the lookback window to train. Off by default.
